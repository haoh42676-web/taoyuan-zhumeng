## 项目流程

事实核验 → 小桃满与渠道表达 → 消费者咨询 → 客户卡 → 原渠道成交台账 → 发货签收 → 售后回访 → 经营复盘 → 更新内容和规则。

网站资料通过后台对应栏目维护，涵盖商品、批次、IP角色与栏目、调查、访谈、路线、FAQ、赛事讲解、渠道模板和网站设置。资料导入先创建私有档案及草稿，人工核验、脱敏、审核后才发布。

经营工作流包括客户、订单、市场问题、建议、实验、协作者和青年协作任务。状态转换、数量金额、库存占用和任务验收在服务端校验。访问分析与经营看板分别统计。调查样本产业端206、消费者243、学生与OPC437分别引用，研究数据不计作经营成果。

正式数据与模拟数据分开：正式看板无签收订单时可查看醒目标记的内存示例；完整业务演练存于独立 peach_demo schema，静态演练只保存在当前浏览器。模拟数据不构成销量、合作或营销效果证明。

## 智能辅助与功能边界

正式客服和后台商品文案已接入服务端主模型。主接口六秒内未完成、报错或未通过事实检查时取消，尝试备用，再失败则使用规则。DeepSeek备用接口已保留，现有凭据尚未通过鉴权；GLM暂不接入。推荐采用可解释规则。

客服覆盖选桃、售后及项目调研、IP营销、青年协作、赛事、合作等公开信息，拒绝完全无关问题。只向模型发送相关公开脱敏事实，不外发原始用户问题、私有资料或订单。密钥仅存服务端环境配置。

付款、退款、物流执行、社交发布及协作结算在原渠道完成，系统登记凭据和状态。没有接入支付执行、实时物流或社交自动发布。IP营销、复购与效率效果仍需真实试行验证。

## 本地运行与验证

Node.js 22.16以上（22或24）+ Express；原生HTML/CSS/JavaScript前台，同域 /api 接口连接后台。配置 DATABASE_URL 时使用远端PostgreSQL；本地无该配置时使用PGlite持久化数据库。

安装 npm ci，启动 npm start，或双击“启动后台.cmd”。本地前台 http://localhost:8787/，后台 http://localhost:8787/admin/。首次本地管理员信息在 .data/first-login.txt，首次登录必须改密。

npm test 使用独立测试数据库；浏览器专项位于 tests 目录。实际业务迁移请使用后台备份，不要删除 .data/postgres。GitHub Pages不能运行Node后台，静态模式不能持久保存正式业务或保管模型密钥。
